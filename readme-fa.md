# فروشگاه دوک — نسخه یکپارچه Netlify + Adin + Supabase

## امکانات
- دریافت کاتالوگ فروشگاه، تنوع‌ها، قیمت و موجودی دقیق هر SKU از سرویس‌های مستند `get_products` برای فهرست کالاها و `get_skus` برای تنوع‌ها و موجودی هر تنوع (با `only_available=0` تا تنوع‌های ناموجود نیز برای نمایش وضعیت برگردند).
- انتخاب تنوع در صورت نامشخص بودن موجودی مسدود نمی‌شود؛ فقط موجودی صفرِ تأییدشده ناموجود است.
- جابه‌جایی تصاویر کالای مادر و تنوع‌ها با کشیدن تصویر به چپ و راست در صفحه محصول.
- گالری مستقل چندتصویری برای کالای مادر و هر تنوع/SKU؛ بارگذاری چند عکس، انتخاب کاور، مرتب‌سازی و حذف.
- ثبت سفارش در جدول `public.orders` در Supabase به‌جای اتکا به localStorage.
- پنل مدیریت سفارش‌ها: مشاهده جزئیات، لغو و تأیید دستی.
- پس از تأیید مدیر، فاکتور با `create_online_order` در آدین ثبت می‌شود؛ `paid` ارسال نمی‌شود، `trust_client_price=0` و `order_key` یکتا برای جلوگیری از تکرار استفاده می‌شود.
- پنل تنظیمات فروشگاه: نام و شعار، نوار اعلان، تلفن‌ها و شبکه‌های اجتماعی، هزینه ارسال و حد ارسال رایگان، بنر، اسلایدر، رنگ‌بندی، نمایش بخش‌های صفحه اصلی و محتوای صفحات.

## فایل‌ها
- `index.html`: فروشگاه مشتریان.
- `admin.html`: پنل مدیریت در `/admin`.
- `netlify/functions/adin-proxy.mjs`: پراکسی امن API آدین برای خواندن کالا و تنوع‌ها.
- `netlify/functions/gallery.mjs`: API گالری تصاویر Supabase.
- `netlify/functions/orders.mjs`: ثبت سفارش و گردش تأیید/ثبت فاکتور.
- `netlify/functions/settings.mjs`: دریافت و ذخیره تنظیمات عمومی سایت.
- `netlify.toml`: مسیرهای API و تنظیمات Netlify.
- `package.json`: وابستگی ثابت `@netlify/identity` برای تأیید امن نشست مدیر در سمت سرور.

## متغیرهای محیطی Netlify
در Site configuration → Environment variables تعریف کنید؛ Scope باید شامل Functions باشد:
- `ADIN_API_URL` = `https://adinapp.ir/api/api.php`
- `ADIN_API_KEY` = کلید API آدین
- `SUPABASE_SERVICE_ROLE_KEY` = کلید Secret پروژه Supabase

هر سه متغیر باید Secret باشند. کلید Supabase هرگز نباید در کد مرورگر یا فایل ZIP قرار گیرد. متغیرهای محیطی فقط در Functions خوانده می‌شوند.

## انتشار
1. ZIP را در Netlify سایت `duke11` به‌صورت Manual deploy منتشر کنید.
2. Netlify Identity را فعال و حساب مدیر `majidboushi@gmail.com` را دعوت/تأیید کنید.
3. وارد `/admin` شوید. توابع مدیریت با `getUser()` رسمی Netlify Identity در سمت سرور، ایمیل مدیر را بررسی می‌کنند.
4. قبل از استفاده واقعی، ثبت سفارش و ایجاد فاکتور را با یک سفارش آزمایشی کم‌ریسک بررسی کنید.
5. تنظیمات عمومی و گالری را از پنل مدیریت کنترل کنید.

## نکته مهم درباره سفارش
سفارش جدید در وضعیت `pending_confirmation` ذخیره می‌شود. تنها با اقدام صریح مدیر به آدین ارسال می‌شود. در درخواست آدین فیلد `paid` وجود ندارد؛ بنابراین پرداختی ثبت نمی‌شود. آدین مرجع نهایی قیمت و موجودی هنگام ثبت فاکتور است. اگر پاسخ آدین مبهم باشد، از تکرار دستی چندباره خودداری کنید؛ `order_key` ثابت برای جلوگیری از فاکتور تکراری در retry استفاده می‌شود.

## محدودیت‌های فعلی
- ویرایش قیمت، موجودی، مشخصات پایه و SKUها همچنان در نرم‌افزار آدین انجام می‌شود؛ سایت مرجع اصلی کالا نیست.
- بخش‌های عمومی سایت و متن صفحات از پنل قابل تنظیم‌اند؛ برای تصاویر بنر و اسلایدر، عکس را مستقیماً از گوشی یا رایانه انتخاب و بارگذاری کنید؛ لینک تصویر لازم نیست و لینک مقصد بنر اختیاری است.
- اتصال زنده آدین و رفتار پاسخ API باید پس از انتشار با سفارش آزمایشی بررسی شود.


### تصویر اصلی و اسلایدهای تکمیلی
تصویر اصلی کالای مادر و تصویر اصلی هر تنوع از خود آدین خوانده می‌شود و همیشه اسلاید اول است. تصاویر بارگذاری‌شده در پنل فقط اسلایدهای بعدی هستند و جای عکس اصلی آدین را نمی‌گیرند. موجودی هر تنوع نیز با شناسه همان SKU از پاسخ موجودی آدین تطبیق داده می‌شود.


### نسخه ۸
- مشکل انتخاب کارت تنوع اصلاح شد؛ شناسه تنوع از طریق ویژگی امن `data-sku` به دکمه منتقل می‌شود تا شناسه‌های متنی آدین باعث خراب‌شدن رویداد کلیک نشوند.
- منطق دریافت کالا و موجودی نسخه ۷ بدون تغییر حفظ شده است.


## اصلاحات نسخه ۹
- پیگیری سفارش از دیتابیس انجام می‌شود و با شماره سفارش + موبایل ثبت‌شده تطبیق داده می‌شود؛ اطلاعات شخصی مشتری در پاسخ عمومی نمایش داده نمی‌شود.
- بنرهای اسلایدر فقط از تصاویر ذخیره‌شده در تنظیمات مدیریت ساخته می‌شوند؛ اسلایدهای خالی و بنر پیشنهاد ویژه بدون تصویر مخفی می‌شوند و تصاویر پیش‌فرض دیگر جایگزین بنرهای مدیریت‌شده نمی‌شوند.
- این نسخه باید در Netlify منتشر شود؛ آزمایش زنده روی سایت انجام نشده است.


## نسخه ۱۰ — بهبود سرعت، بنرها و حالت شب
- تنظیمات بنر و محتوای مدیریت‌شده بعد از هر بار رندر مجدد صفحه دوباره اعمال می‌شود تا با به‌روزرسانی فهرست کالاها ناپدید نشود.
- دریافت فهرست کالاها و تنوع‌ها به‌صورت هم‌زمان انجام می‌شود؛ کش نسخه قبل نیز برای نمایش سریع اولیه حفظ شده است.
- بارگذاری تصاویر بهینه‌تر شده و ابعاد بنرها از ابتدا رزرو می‌شود تا صفحه هنگام لود تصویر پرش نداشته باشد.
- حرکت اسلایدر صفحه اصلی نرم‌تر شده است.
- کلید حالت شب/روز به سربرگ فروشگاه اضافه شده و انتخاب کاربر ذخیره می‌شود.

**توجه:** این نسخه از نظر ساختار ZIP و syntax بررسی شده؛ برای تأیید عملکرد واقعی باید روی Netlify منتشر و با API آدین و تنظیمات بنر فروشگاه آزمایش شود.


## نسخه ۱۲ — گردونه شانس و دعوت دوستان
- پاپ‌آپ گردونه در ورود مشتری نمایش داده می‌شود و شماره موبایل می‌گیرد؛ طبق درخواست، هیچ پیامک یا کد تأییدی ارسال نمی‌شود.
- هر شماره موبایل یکتا یک شانس اولیه دارد. ثبت شماره جدید با لینک معرف، یک شانس اضافه به معرف می‌دهد. لینک دعوت با کد اختصاصی مشتری ساخته می‌شود.
- احتمال جوایز در سمت سرور تعیین می‌شود: ۴۵٪ تخفیف ۵٪، ۳۵٪ بن ۲۰۰ هزار تومان، ۱۰٪ تخفیف ۱۰٪، ۸٪ شال رایگان و ۲٪ بن ۵۰۰ هزار تومان.
- نتیجه هر چرخش در دیتابیس ذخیره می‌شود و کد اختصاصی جایزه به مشتری نمایش داده می‌شود. درخواست تکراری یک چرخش، جایزه دوم مصرف نمی‌کند.
- پنل مدیریت، بخش «گردونه شانس» دارد و شماره برنده، جایزه و کد جایزه را نشان می‌دهد.
- به دلیل غیرفعال بودن پیامک، مالکیت شماره تأیید نمی‌شود؛ محدودیت درخواست بر اساس IP و یکتایی شماره فقط سوءاستفاده را محدود می‌کند و مانع کامل شماره جعلی یا خودمعرفی نمی‌شود.
- در این نسخه، کد جایزه برای بررسی و اعمال دستی توسط پشتیبانی/فروشگاه است و هنوز به‌صورت خودکار در تسویه‌حساب تخفیف را اعمال نمی‌کند.
- جدول‌ها و توابع گردونه در Supabase پروژه `dook-store` ایجاد شده‌اند؛ فایل ZIP را نیز باید در Netlify منتشر کنید تا رابط کاربری و API فعال شوند.

### متغیرهای لازم
همان متغیرهای قبلی کافی هستند: `SUPABASE_SERVICE_ROLE_KEY` باید در Netlify فقط سمت Functions و به‌صورت Secret در دسترس باشد. متغیر یا کلید جدیدی لازم نیست.
